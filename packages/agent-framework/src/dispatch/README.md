# Native Dispatch contract

`kapelle/dispatch` v1 is an immutable request and lineage record. It adds no scheduler and owns no Task status. `kilgore/task` v1 continues to own the commitment and completion; `kilgore/report` v1 retains the original deliverable. The legacy agent queue's `DispatchDoc`, `DispatchEntryDef` and `dispatch.operation.v1` are typed queue/envelope representations, not native models.

`CREATE_DISPATCH` fixes the existing Task authority/ref/commitment hash, original requester, authenticated immediate sender, sender and recipient definition versions/hashes, exact instructions, source content versions/hashes, scope, permission, expiry, parent/hash and optional continuation. `ACCEPT_DISPATCH` binds the receiving principal to that exact input. `REQUEST_DISPATCH_CANCEL` records a request without asserting an external effect stopped. `RECORD_DISPATCH_RESULT` retains one original Report content/verification reference, including after cancellation when a trusted result actually exists.

`FrameworkAuthority.dispatchCommand(request, authenticatedPrincipalId)` is an in-process integration seam. The host must derive that principal from a separately scoped machine credential; HTTP request JSON never selects it. The seam cannot operate ReviewIntent or mint an owner decision. Dispatch request identity includes principal identity so an accepted retry cannot be borrowed by another principal. Allocation remains an owner-scoped service operation pending machine provisioning integration.

The service loads native parents and agents from its owned backend. Every hop independently checks owner/scope, pinned qualified definition/runtime/READY state, permission grants, expiry, source content and the current Task commitment. Children preserve the parent's original requester and commitment, and their sender must be its recipient. Traversal allows at most eight ancestors; cycles, self-dispatch and unverified continuations fail. Instructions never grant capabilities. The trusted Task/source readers must enforce their own authoritative scope and content semantics.

`dispatchBundle` reconstructs work from retained records, with no chat history. Only the intended recipient can receive an active bundle. Cancelled or completed work is not returned as active work. Owner-scoped historical reads remain available. A continuation is a new Dispatch, referring to verified ancestry, with new instructions and a new content hash. Changed publication content creates a new native ReviewIntent and needs its own owner decision. A result does not finish the Task or parent Dispatch.

For delegated publication, immutable manifest `originDispatch` supplies the native document ID/hash. The publication policy requires an accepted current origin and independently validates every ancestor and agent at reservation, invocation claim and immediate admission. The native ReviewIntent owns the one-shot effect reservation/attempt and verification history. Provider uncertainty only permits receipt reconciliation of that same operation; it never resets the claim.

## Integration obligations

Production must bind actual Task/Report readers and verifier facts; install a credential-to-principal adapter; and qualify the provider's serialization, immediate preconditions and unique-operation reconciliation. The publication queue's `ensure` must atomically enforce the exact intent for a stable key, and its projection must not execute independently of native admission. No code here installs credentials, migrates records, marks a Task complete or makes a provider call by default.

Task execution is Framework-managed; there is no Manager queue bridge in the Task path. `TaskDelegations` creates the native Dispatch with `CREATE_DISPATCH` (`../task-delegation/adapter.ts`). `TaskWorker` reads `dispatchBundle` and records `ACCEPT_DISPATCH` and `RECORD_DISPATCH_RESULT` through `dispatchCommand` (`../task-delegation/worker.ts`; see [WORKER.md](../task-delegation/WORKER.md)).

Qualification uses real generated models and isolated Reactor storage. `tests/dispatch-publication-trace.test.ts` additionally imports the existing Task and Report models from `KAPELLE_PLATFORM_MODELS_ROOT`, verifies native replay against saved state, exports ZIPs, and uses fake source/build/provider and Manager queue ports. Set `KAPELLE_NATIVE_TRACE_OUTPUT` to retain both successful native traces. This proves model/receipt/cold-start behavior, not production gateway authentication or live provider safety.
